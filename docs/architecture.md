# «Кафе желісінің ақпараттық жүйесі» архитектуралық диаграммасының сипаттамасы

### 1. Диаграмманың мақсаты

«Кафе желісінің ақпараттық жүйесі» архитектуралық диаграммасы жүйенің негізгі компоненттерін, олардың міндеттерін және өзара байланыстарын сипаттайды.

Жүйе **үш деңгейлі архитектура (Three-Tier Architecture)** негізінде жобаланған:

1. Презентация деңгейі (Presentation Layer).
2. Қолданбалы логика деңгейі (Application / Business Logic Layer).
3. Деректер деңгейі (Data Layer).

Бұл архитектура пайдаланушылардың сұраныстарын өңдеуге, тапсырыстарды басқаруға, төлемдерді тіркеуге және ақпаратты SQL Server дерекқорында сақтауға мүмкіндік береді.

### 2. Презентация деңгейі (Presentation Layer)

Презентация деңгейі пайдаланушылардың ақпараттық жүйемен өзара әрекеттесуін қамтамасыз етеді.

Жүйеде алты негізгі пайдаланушы рөлі қарастырылған:

- **Клиент** — мәзірді қарайды, тағамдарды іздейді және тапсырыс қалыптастырады.
- **Официант** — мәзірмен жұмыс істеп, клиенттердің тапсырыстарын қалыптастырады.
- **Кассир** — тапсырыстарды және төлемдерді тіркейді.
- **Асүй қызметкері** — тапсырыстың орындалу мәртебесін өзгертеді.
- **Филиал менеджері** — есептер қалыптастырады және мәзірді басқарады.
- **Жүйе әкімшісі** — пайдаланушыларды және мәзірді басқарады.

Бұл деңгейдің негізгі компоненті — **Пайдаланушы интерфейсі (User Interface / UI)**.

Интерфейс құрамына жүйеге кіру формасы, мәзірді қарау және іздеу беттері, тапсырысты рәсімдеу формасы, төлемді тіркеу экраны және басқару панельдері кіреді.

Пайдаланушы интерфейсі енгізілген мәліметтерді қолданбалы логика деңгейіне жібереді және өңдеу нәтижелерін экранда көрсетеді.

### 3. Қолданбалы логика деңгейі (Business Logic Layer)

Қолданбалы логика деңгейі ақпараттық жүйенің негізгі функцияларын орындайды және пайдаланушылардан келетін сұраныстарды өңдейді.

Бұл деңгейде келесі компоненттер қарастырылған:

**Авторизация модулі.** Пайдаланушының жүйеге кіруін тексереді және оның рөліне сәйкес функцияларға қол жеткізуін басқарады.

**Мәзірді басқару модулі.** Тағамдар мен сусындарды іздеу, қарау, қосу, өзгерту және мәзір санаттарын басқару операцияларын орындайды.

**Тапсырыстарды басқару модулі.** Жаңа тапсырыстарды қалыптастыруға, тіркеуге және олардың орындалу мәртебесін өзгертуге жауап береді.

**Төлемдерді басқару модулі.** Тапсырыстар бойынша төлем ақпаратын тіркейді және тиісті төлем жазбаларын өңдейді.

**Есеп беру модулі.** Тапсырыстар мен төлемдер туралы деректер негізінде филиал қызметіне қатысты есептер қалыптастырады.

Қолданбалы логика деңгейі дерекқормен тікелей емес, деректерге қол жеткізу компоненті арқылы әрекеттеседі.

### 4. Деректер деңгейі (Data Layer)

Деректер деңгейі ақпаратты сақтау, іздеу, өзгерту және жою операцияларын қамтамасыз етеді.

Бұл деңгей екі негізгі компоненттен тұрады.

**Деректерге қол жеткізу компоненті (Data Access Layer — DAL).** Қолданбалы логикадан келетін сұраныстарды қабылдап, дерекқорға қажетті SQL операцияларын орындайды. Сонымен қатар алынған мәліметтерді қолданбалы логика деңгейіне қайтарады.

**Дерекқор (Microsoft SQL Server — CafeNetworkDB).** Жүйенің негізгі ақпаратын сақтайды.

GitHub-та сақталған SQL нұсқасында келесі кестелер қарастырылған:

- `Branches` — филиалдар туралы мәліметтер.
- `Roles` — пайдаланушы рөлдері.
- `Users` — пайдаланушылар туралы ақпарат.
- `Categories` — мәзір санаттары.
- `MenuItems` — тағамдар мен сусындар.
- `Orders` — тапсырыстар.
- `OrderItems` — тапсырыс құрамындағы өнімдер.
- `Payments` — төлемдер туралы ақпарат.

### 5. Компоненттер арасындағы бағытталған байланыстар

Диаграммада компоненттердің өзара байланыстары бағытталған жебелер арқылы көрсетіледі.

**Сұраныс бағыты:**

Пайдаланушы → Пайдаланушы интерфейсі → Қолданбалы логика → Деректерге қол жеткізу компоненті → Дерекқор.

**Жауап бағыты:**

Дерекқор → Деректерге қол жеткізу компоненті → Қолданбалы логика → Пайдаланушы интерфейсі → Пайдаланушы.

Мысалы, клиент мәзірден тағам іздеген кезде сұраныс интерфейстен мәзірді басқару модуліне жіберіледі. Модуль DAL арқылы дерекқордан қажетті тағамдарды алады. Нәтижелер кері бағытта қайтарылып, пайдаланушы интерфейсінде көрсетіледі.

### 6. Архитектураның артықшылықтары

Үш деңгейлі архитектураны қолданудың негізгі артықшылықтары:

- **Модульдік құрылым:** жүйенің әрбір деңгейі жеке міндет атқарады.
- **Қауіпсіздік:** пайдаланушылар дерекқормен тікелей жұмыс істемейді.
- **Кеңейту мүмкіндігі:** жаңа функцияларды қолданыстағы құрылымды толық өзгертпей қосуға болады.
- **Қызмет көрсетудің ыңғайлылығы:** интерфейс, бизнес-логика және деректерді сақтау компоненттерін бөлек жетілдіруге болады.
- **Деректердің бірізділігі:** кафе филиалдарына қатысты ақпаратты орталықтандырылған дерекқорда сақтауға мүмкіндік береді.

### Қорытынды

«Кафе желісінің ақпараттық жүйесі» үшін жобаланған үш деңгейлі архитектура ақпараттық жүйенің негізгі компоненттерін және олардың арасындағы ақпарат алмасу тәртібін көрсетеді.

Диаграммада пайдаланушылар, пайдаланушы интерфейсі, қолданбалы логика модульдері, деректерге қол жеткізу компоненті, SQL Server дерекқоры және бағытталған байланыстар қамтылған.

Осы архитектура кафе желісіндегі тапсырыстарды, төлемдерді, мәзірді және пайдаланушыларды басқару үдерістерін ұйымдастыруға негіз болады.
